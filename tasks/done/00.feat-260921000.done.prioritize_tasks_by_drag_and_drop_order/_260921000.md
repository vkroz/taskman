Let users prioritize work directly in the task list by dragging a task to a new vertical position. The persisted vertical order is the priority order: a task moved upward has higher priority, and a task moved downward has lower priority.

## Scope

- Reorder a task within the displayed task list by drag and drop.
- Update the displayed list immediately to the accepted drop position.
- Persist the resulting order and restore it after refresh or reopening Taskman.
- Expose the same ordering mutation through the Taskman CLI, consistent with the product's UI/CLI parity rule.

## Boundaries

- Reordering does not move a task to another list or collection.
- Reordering does not change the task's parent, lifecycle status, type, or other metadata except the ordering state required to represent priority.
- This story does not add unrelated prioritization methods or define future stories.

## Acceptance criteria

- A user can drag a task to a different position within the displayed task list.
- After a valid drop, the displayed order matches the drop position.
- Moving a task upward makes it higher priority than the tasks it passed; moving it downward makes it lower priority than the tasks it passed.
- The new order persists and is restored after refreshing or reopening Taskman.
- Reordering does not implicitly change the task's parent or lifecycle status.
- The CLI can perform the equivalent ordering change and reports invalid reorder requests without partially changing the stored order.

## Local verification

- Automated tests cover upward, downward, first-position and last-position moves; persistence across a fresh read; unchanged parent and lifecycle status; and atomic rejection of invalid requests.
- A browser walkthrough drags tasks upward and downward, confirms the immediate order, refreshes or reopens the UI, and confirms the same order and unchanged task metadata.
- Run the full test suite and `taskman validate`.
