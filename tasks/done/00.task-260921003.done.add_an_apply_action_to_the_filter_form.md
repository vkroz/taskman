The existing general-purpose metadata filter form lets a user configure criteria but provides no action that applies them to the task list.

## Reproduction

1. Open the task-list workspace.
2. Activate the existing `＋ Filter` control to add a filter row.
3. Choose a metadata attribute and operator, then enter a value.
4. Try to apply the configured filter.

## Actual behavior

There is no command, button or other clear action to apply the configured filter, so the user cannot update the displayed work-item list from the form.

## Expected behavior

The filter form exposes a clear, usable action that applies the configured metadata filters and updates the displayed work-item list.

## Acceptance criteria

- A user who configures a metadata filter can activate a clearly labeled apply action from the filter form.
- Activating the action applies the current attribute, operator and value and renders matching results with any contextual ancestors required to preserve hierarchy.
- The action is keyboard operable, has an accessible name and presents an understandable state.
- Invalid or incomplete input does not silently appear to succeed; the UI identifies what the user must correct.
- Existing filter removal and `Clear filters` behavior remain available.
- The fix does not change filtering semantics, work-item metadata, hierarchy or lifecycle status.
- The dedicated hide-done control remains a separate story. No ascending/descending sorting or sort-direction control is added.

## Local verification

- Add a regression test that reproduces the missing action, applies configured criteria through the new action and asserts the resulting list and hierarchy context.
- Cover keyboard activation, accessible naming, invalid or incomplete input, filter removal and `Clear filters` regression behavior.
- In a browser, follow the reproduction steps and confirm the action is visible, usable and updates the list without changing sorting.
- Run focused UI tests, the full test suite and `taskman validate`.
