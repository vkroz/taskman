## Outcome

A storage interface exists with a file backend for every read operation. Read-only commands use it.

## Scope

- Interface and backend-neutral item record (fields, body, journal, parent, dependencies, order).
- Backend selection from configuration. `file` is the only accepted value. An unknown value fails with a clear message.
- File backend reads: find by ID, iterate items, children, ancestors, dependency graph, consolidated history.
- Move these commands to the interface: `show`, `list`, `context`, `ready`, `dependents`, `waiting-on`, `search`, `browse`, `history`, `worktree-status`.
- Start the contract test suite with read cases. It must accept another backend later without changes to the test cases.

## Acceptance criteria

- Modules that hold only read commands (`show.py`, `list_cmd.py`, `queries.py`, `search.py`, `worktree_status.py`) import none of `model.layout`, `model.names`, `model.yaml_io`.
- In `context.py` and `collection.py`, the read commands (`context`, `browse`, `history`) use only the interface. Those modules also hold write commands; their imports clear in 261109001.
- All tests on `main` pass with unchanged assertions.
- Contract read cases pass against the file backend.
