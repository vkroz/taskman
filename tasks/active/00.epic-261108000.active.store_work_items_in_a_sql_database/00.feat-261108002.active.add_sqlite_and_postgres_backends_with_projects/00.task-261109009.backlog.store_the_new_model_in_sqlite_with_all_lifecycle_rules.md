## Outcome

The SQLite backend stores the new model, and every lifecycle rule of epic R1 holds on it.

## Scope

- Store implementation for SQLite, scoped by project.
- Lifecycle rules apply to the new model: comments replace journal entries; every field change writes an activity entry.
- One lifecycle operation runs in one transaction; the store lock covers it.
- The contract suite is rewritten for the new model and is backend-parametrized. It includes every R1 rule, project isolation, concurrent writers and the last-change time.

## Acceptance criteria

- The contract suite passes against SQLite without Docker.
- Two processes writing concurrently produce no lost updates and no duplicate keys.
- Two projects in one database do not see each other's items.
