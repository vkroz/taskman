## Outcome

Work items persist in SQLite or Postgres with the work-item model of decision D5 (projects, keys such as TM-42, typed comments, dependency links, activity history, assignees, labels). The CLI and the workspace UI work on that model. All lifecycle rules of epic R1 hold.

## Requirements

Covers epic R1–R7 and R11 for the `sqlite` and `postgres` backends.

- A data model document defines entities, fields, keys and how each lifecycle rule applies to them. It is approved before the schema is built.
- Configuration follows D6 and D7: environment variables, also read from `.env`; SQLite defaults to `~/.local/share/taskman/taskman.db`. Postgres connects by connection string or Cloud SQL unix socket. The password comes from an environment variable or a mounted secret file.
- An item key identifies the item and its project. A new top-level item names its project; listings filter by project on request.
- A schema upgrade command records and applies versions in order.
- Comments replace journal entries. Each comment has a kind (decision, progress, handoff, summary, verification) and verification comments carry a result.
- Every change to a work item's fields is recorded in its activity history with author and time.
- Consolidation is not provided (D8).

## Acceptance criteria

- The contract suite, rewritten for the new model, passes against SQLite and against Postgres 16, including every R1 rule and a check of the last-change time.
- With two projects in one database, `--project` filters return only that project's items, and keys stay unique across projects.
- Concurrent writers from two processes produce no lost updates and no duplicate keys.
- The upgrade command on a current database exits 0 and changes nothing.
- The suite runs without Docker when only SQLite tests are selected; Postgres tests run when a test database URL is set and are reported as skipped otherwise.
- The CLI and the UI create, read and change comments, assignees and labels, and show activity history.
- No command, help text or UI check assumes 9-digit IDs.
- `taskman help` and the README describe every storage setting: `TASKMAN_BACKEND`, connection and password source. Each backend has one worked example: SQLite, local Postgres, Cloud SQL socket.

## Verify

`cd taskman && uv run pytest` with and without a Postgres test database URL.
