## Outcome

SQL is Taskman's only storage (decision D1 revised). File-backend code, file-only commands and `tasks/` layout documentation are gone. SQL storage starts clean; nothing is imported from `tasks/` (decision D4).

## Requirements

- Remove the file backend and its model modules, and commands that exist only for the file layout: `migrate`, `worktree-status`, `consolidate`, `history`, and validate's layout checks. `TASKMAN_TASKS_DIR` and `file` as a `TASKMAN_BACKEND` value stop working with a clear message.
- `taskman help`, the README, `docs/`, `AGENTS.md`, `CLAUDE.md`, and the plugin's skills, rules and workflow reference describe only the SQL model.
- Files under `tasks/` stay in the repository as historical text. Taskman does not read them.

## Acceptance criteria

- A search of `taskman/src` finds no file-backend module or `tasks/` layout code.
- The full test suite passes against SQLite with no file-backend tests left.
- A search of docs, plugin sources and agent instructions finds no instruction to use `tasks/` files or journal kinds as file frontmatter.
- With the file backend selected, every command stops with a message that names the SQL settings.

## Verify

`cd taskman && uv run pytest`; text searches over `taskman/src`, `docs/`, `plugins/tm/`, `AGENTS.md`, `CLAUDE.md`.
