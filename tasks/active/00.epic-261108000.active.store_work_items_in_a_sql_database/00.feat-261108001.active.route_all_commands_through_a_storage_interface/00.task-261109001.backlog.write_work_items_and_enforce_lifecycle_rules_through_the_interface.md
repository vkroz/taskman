## Outcome

Every mutation goes through the storage interface. Lifecycle rules live in one backend-neutral layer.

## Scope

- Interface writes: create (with ID allocation), update, edit with reason, depend, record, finalize, move (with subtree), convert, discard, close, reorder, consolidate.
- Lifecycle rules run once, above the backend: draft and finalize, journal kinds and verification results, close gates (current summary, current passing verification, finished dependencies and descendants), immutability of closed items, revision invalidation of ancestors, cycle rejection, task-is-leaf.
- File backend keeps its mutation lock and atomic writes.
- Move these commands to the interface: `new`, `finalize`, `update`, `edit`, `record`, `depend`, `discard`, `move`, `convert`, `close`, `reorder`, `consolidate`.
- Contract write and rule cases, including two concurrent writers.

## Acceptance criteria

- The listed command modules import none of `model.layout`, `model.names`, `model.yaml_io`.
- No lifecycle rule check remains inside the file backend.
- All tests on `main` pass with unchanged assertions.
- Contract write and rule cases pass against the file backend.
