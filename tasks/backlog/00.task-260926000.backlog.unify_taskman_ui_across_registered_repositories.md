## Outcome
A developer sees and manages tasks from several repositories, projects, and companies in one local Taskman UI at one address. Each repository's task tree remains the source of truth.

## Agreed direction
- Run one local UI server over explicitly registered repository task trees. Do not require a server or URL per repository.
- Label each registration with its company and project; a project may group several repositories. Show the task's source wherever it matters.
- Read and write through the same UI, routing each operation to the registered source. Keep repository-local files, CLI use, and agent workflows intact.
- Run with the developer's existing operating-system file access. Task operations must be limited to registered roots. Company and project labels organize work; they do not enforce access control.

## Acceptance criteria
- A developer can register and remove task trees, assign company and project labels, and retain those registrations across UI restarts.
- One URL supports navigation and search across all registered task trees, with clear company, project, and repository context.
- Task details, creation, and editing operate on the intended tree from that URL. Tasks with the same local ID in different trees remain distinct.
- Missing or unreadable registered trees are reported without hiding usable trees. Requests cannot select an unregistered tree for task operations.
- Existing repository task files and CLI behavior remain usable. Local verification covers two or more trees, duplicate IDs, routed writes, unavailable roots, and the full test suite.

## Scope boundary
This task does not add project-level task trees, product documentation, agent launch or monitoring, shared-user access control, or a central task store. Those remain separate decisions.
