Let users exclude completed work from the task list with one dedicated action, without opening or configuring the general-purpose field filter.

## Scope

- Replace the unnecessary ascending/descending sort-direction controls in the task-list control area with a dedicated control that toggles exclusion of tasks whose status is `done`.
- Keep the existing general-purpose field filter available for arbitrary metadata queries.
- Make the dedicated control's active state visible without relying only on color.
- Apply the exclusion together with the selected view, keyword search, epic scope and general-purpose field filters.

## Filter behavior

- Activating the control removes `done` tasks from the displayed results.
- Deactivating it allows `done` tasks to appear again, subject to every other active constraint.
- The exclusion combines with the general filter using logical AND. If the general filter requests only `done` work while the exclusion is active, no done rows appear; deactivating the exclusion restores the general filter's matching done rows.

## Boundaries

- The dedicated control supplements rather than replaces the general-purpose field filter.
- No ascending/descending sorting or sort-direction control is required or added. This story replaces those unnecessary controls with the hide-done action rather than adding unrelated sorting behavior.
- No unrelated task-list controls or filtering modes are included.

## Acceptance criteria

- A user can hide all `done` tasks with one action from the task list without opening the general filter form.
- The dedicated hide-done control occupies the task-list control area in place of the unnecessary ascending/descending sort-direction controls.
- The active state is visible, accessible without color alone and remains accurate while other filters are changed.
- Deactivating the control restores done tasks that satisfy the selected view and remaining active search, epic-scope and field-filter constraints.
- General filter criteria remain available and work while the dedicated exclusion is on or off, including the conflicting `status = done` case defined above.
- No ascending/descending sorting capability or sort-direction control is added.

## Local verification

- Automated UI or query-state tests cover rendering, toggle on, toggle off, visible active state, composition with view/search/epic scope and general filters, the `status = done` conflict, and preservation of other filter criteria.
- A browser walkthrough uses mixed `backlog`, `active` and `done` work to exercise the control alone and with other filters, confirming the displayed rows and active state at each transition.
- Confirm the unnecessary ascending/descending controls were replaced and no sort-direction control was added.
- Run focused UI tests, the full test suite and `taskman validate`.
