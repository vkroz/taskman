# Taskman workspace design

Make the work collection the primary surface. Use a quiet light canvas, dark ink, restrained indigo accents, consistent 8px spacing, 14px body type, rounded controls and visible keyboard focus. The left navigation offers All work, Current, Backlog and Done. The central hierarchical list uses aligned status, type and priority columns; clicking a title opens an optional details panel. Narrow screens stack panels without horizontal page overflow.

Rows have distinct expand buttons and a drag handle; rows have no selection checkboxes. Collapse state survives refresh. Search and filters retain matching descendants with dimmed contextual ancestors; a contextual ancestor is explicitly labeled and is not counted as a match. Sorting applies within siblings with the key as a deterministic tie breaker, so `TM-10` follows `TM-9`. Dragging an open item changes its position among its siblings; done items cannot be dragged. Filters combine with AND; comma-separated exact values within a field use OR. Contains searches nested values as text; exists detects field presence. Every metadata field of the items is offered, including project, assignee, labels and the comments in `journal`, with parent_id added as a derived attribute. Epic scope includes its descendants. Empty results offer Clear filters.

Creation and editing use a labeled dialog. A top-level item needs a project key; a child uses the project of its parent. Editing supports title and description of open work and records a reason as a decision comment by the store actor. A draft can have an empty description. Completed records remain read-only. Delete is intentionally limited to unreferenced draft leaves, matching the existing discard contract; finalized work remains durable. Commands explain ineligible actions. Details show metadata, body, attributed comments and the activity history. Add comment and Assignee and labels open their own dialogs, so the 5-second refresh cannot discard typed text; a verification comment requires a result. Escape or Close returns space to the collection. Agents finalize, move and close items through the CLI.

Visual checks: no horizontal page overflow at desktop or phone widths; titles wrap without overlapping controls; statuses are readable without color alone; every input has a label; focus is visible; empty and error states identify a recovery action. Walkthrough: switch Current/Backlog/Done, scope an epic, combine keyword and metadata, sort siblings, drag an open item, collapse a branch, dismiss/reopen details, create/edit/discard an eligible draft, add a comment, set an assignee and labels. The browser must remain functional offline.

Implementation uses a shared Python query service for CLI and UI. `taskman browse` accepts `--where FIELD=VALUE`, `--contains FIELD=TEXT`, `--exists FIELD`, `--missing FIELD`, `--keyword`, `--epic`, `--project`, `--sort` and `--descending`. Exact matches support comma-separated alternatives; nested structures use contains. JSON rows mark contextual ancestors explicitly.

## Workspace server

`taskman ui` serves the page at `/` and at an item path such as `/TM-7`. The page reads its state from the query string. Every API error is JSON with an `error` text. Mutations need the `X-Taskman: 1` header and a local `Host`.

- `POST /api/query` returns the projects with open counts, the item count of each view, facet counts, and the rows of one view. A row has no description, journal or internal fields. It has derived signals: state, blockers, leaf progress, latest verification, attention reason and last update. The response has an `etag`. When the request sends the same `etag`, the response is only `{etag, unchanged: true}`.
- The views are Attention, Active, Ready, Blocked, Drafts, Backlog and Done. Attention holds open items with a failed or blocked current verification, a handoff as the latest comment, or all close gates passed. Ready holds backlog items that can start. Blocked holds finalized open items that are not ready.
- `GET /api/show/KEY` adds ancestors, children, dependencies, dependents, the close gates and whether the item can be discarded, with the reason when it cannot. `taskman close` uses the same close gates.
- `POST /api/edit` with `base_title` and `base_body` returns 409 with the current text when another actor changed the title or description after the editor opened. Comments, assignee and label changes do not cause a conflict.
- `POST /api/fields` sets the assignee and the labels in one transaction.
- `POST /api/reorder` moves an item among its siblings. The top-level items of each project have their own order.
